# Data Model: Local API Tester

Conceptual model of the entities the API Tester manipulates. Nothing here is a formal schema —
DevDB stores plain JSON, `localStorage` stores JSON strings, and the sandbox worker's protocol is a
`postMessage` shape. Field names below match the actual JS property names in
`static/api-tester.js` / `static/collection-utils.js` / `static/cookie-jar.js`.

## Persistence map

| Entity | Where it lives | Survives `.dsb` export/import? |
|---|---|---|
| Collection items + folder auths | DevDB `collections` store (`/api/collections`) | Yes |
| Environments | `localStorage` (`devsuite-api-environments`) | **No** — browser-local only |
| Active environment id | `localStorage` (`devsuite-api-active-env`) | No |
| Request history (last 50) | `localStorage` (`devsuite-api-history`) | No |
| Cookie jar | In-memory array, page lifetime only | No — and never DevDB-eligible by design |
| Runtime variables | In-memory object, reset per Send / per Run | No |
| OAuth2 cached token | In-memory variable (`oauth2Token`), cleared on config edit or page reload | No |

## Entities

### Collection Item *(one saved request)*
| Field | Type | Notes |
|---|---|---|
| `name` | `string?` | display name; falls back to URL if absent |
| `method` | `string` | GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS |
| `url` | `string` | may contain `{{var}}` tokens |
| `queryParams` | `{key,value,enabled}[]` | dynamic-list shape; legacy plain-object form also read |
| `headers` | `{key,value,enabled}[]` | same dynamic-list shape |
| `auth` | `AuthConfig` | see below |
| `bodyType` | `'none'\|'json'\|'form-data'\|'text'\|'graphql'` | |
| `body` | `string \| {key,value,enabled}[] \| null` | shape depends on `bodyType` |
| `graphqlQuery` / `graphqlVars` | `string?` | only when `bodyType === 'graphql'` |
| `folder` | `string?` | `/`-separated path; absent = top level |
| `preRequestScript` / `testsScript` | `string?` | JS source; executed in the sandbox worker (see spec.md User Story 6) |

### AuthConfig
| `type` | Extra fields |
|---|---|
| `none` | — |
| `inherit` | — (resolved at send-time from `folderAuths`, not stored on the item) |
| `bearer` | `token` |
| `basic` | `username`, `password` |
| `api-key` | `headerName`, `headerValue` |
| `oauth2` | `grantType`, `tokenUrl`, `clientId`, `scope` (secret/username/password are UI-only, not persisted on the item — only re-entered per session) |

### Folder *(derived, not stored)*
Not a first-class record. `buildFolderTree()` derives the tree by splitting every item's `folder`
on `/` and grouping. A folder "exists" only as long as at least one item references it (deleting
the last item in a folder makes the folder disappear from the sidebar on next render) **or** a
`folderAuths` entry references it (an auth-only "empty" folder can still appear via the folder-auth
modal's path, though the sidebar itself only renders folders with items).

### Folder Auth Map (`folderAuths`)
`{ [fullFolderPath: string]: AuthConfig }` — sibling structure to the items array, saved together
in the same DevDB write (`{items, folderAuths}`). Resolved by `resolveFolderAuth()` walking from a
request's folder up to the root, returning the first ancestor (inclusive) with a non-`'none'`
entry.

### Environment
| Field | Type | Notes |
|---|---|---|
| `id` | `string` | `crypto.randomUUID()` |
| `name` | `string` | |
| `vars` | `{[key:string]: string}` | plain object, not the dynamic-list shape |

### Cookie Jar Entry
| Field | Type | Notes |
|---|---|---|
| `name` / `value` | `string` | |
| `domain` | `string` | lowercased host or server-widened domain |
| `hostOnly` | `boolean` | true unless server sent an explicit `Domain=` attribute |
| `path` | `string` | defaults to the request path up to the last `/` |
| `expires` | `number \| null` | epoch ms; `null` = session cookie |
| `secure` | `boolean` | if true, only attached over https |

### Runtime Variables
Plain `{[key:string]: any}`, reset to `{}` at the start of every Send and every Run (not per-item
within a run). Written by the script sandbox's `mutations.runtime`; read by `interpolate()` ahead
of environment vars.

### Sandbox Worker Message (protocol, not persisted)
```
init: { kind: 'init', token }                                                — sent once per worker instance
in:   { id, kind: 'pre'|'test', code, codeSig, authToken, runtimeVars, envVars, response }
out:  { id, logs: [{type, text}], results: [{name, passed, error?}], mutations: {runtime:{}, env:{}} }
```
`token` is a random `crypto.randomUUID()` generated by `api-tester.js` when the worker is created
and held only in module scope there and in the worker's `self.__DS_WORKER_TOKEN`. `codeSig` is
HMAC-SHA256(`code`) under `token` (`_signScript`), verified worker-side (`verifySignedScript`)
before `kind` is consulted; `authToken` must equal `token` as a second check.

### History Item
Identical shape to `buildRawConfig()`'s output (raw, pre-interpolation `Collection Item`-like
object) plus a `timestamp` (epoch ms). Capped at 50 entries, newest first.

## Backend-facing shapes (see contracts/http-api.md for full detail)

- `GET /api/collections` → `{items: CollectionItem[], folderAuths: {...}} ` (or `{}` if store empty)
- `POST /api/collections` body: same shape, written verbatim to the DevDB `collections` store —
  the backend does no schema validation of item contents (`data: dict` on the FastAPI handler).
- `POST /api/proxy` body: `{url, method, headers, body}` → response `{proxy_response: true, status,
  headers, set_cookie: string[], body, truncated?}`.
